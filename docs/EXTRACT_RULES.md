# Как составлять rules.json по нормам (инструкция для локальной сессии Claude Code)

Работа ведётся в **локальной** сессии на компьютере пользователя, где лежат PDF с нормами и собранный плагином
`corpus.json`. Правила пишутся только по тексту норм, ничего не берётся из памяти.

## Входные данные

- Папка с нормами: PDF и `corpus.json` в ней (кнопка плагина «Подготовить нормы»). Корпус читаем вместо PDF:
  в нём пункты `{number, page, text}` по каждому документу.
- Формат правил: `docs/RULES_FORMAT.md`; пример: `rules/rules.example.json`; список проверок: `docs/RULES.md`.

## Порядок

1. Взять проверки для начала: `door-width` (A.1.1), `door-swing` (A.1.4), `stair-width` (A.1.3).
2. По `corpus.json` найти пункты, относящиеся к проверке (поиск по словам; открывать нужные пункты целиком).
   Если корпуса нет или пункт читается плохо, открыть PDF на нужной странице.
3. Для каждого найденного требования записать правило:
   - `document`, `edition`, `clause`: обозначение документа, редакция, номер пункта;
   - `quote`: **дословная** короткая цитата из текста пункта (без пересказа);
   - `minWidthMm` и условия `when` (помещения, тип двери, уровень), только то, что прямо следует из пункта;
   - `check`, `subgroup`, `section`: как в `docs/RULES.md`.
4. Условия, которые нельзя однозначно перенести в правило (число эвакуирующихся, исключения, класс здания),
   не придумывать: записать правило без этих условий с пометкой в `title` и перечислить вопросы пользователю.
5. **`approvedBy` и `approvedOn` оставлять пустыми.** Утверждает только человек.
6. Сохранить в `rules.json` в папке с нормами и проверить цитаты:
   `python tools/verify_rules.py <папка с нормами>`. Правила, для которых проверка не прошла, исправить.
7. Пользователь выгружает правила в Excel кнопкой плагина, просматривает по вкладкам, утверждает и загружает обратно.

## Чего не делать

- Не заполнять `approvedBy`, не подбирать значения «по смыслу», не править числа без пункта нормы.
- Не копировать в репозиторий тексты норм: только короткие цитаты в правилах.
