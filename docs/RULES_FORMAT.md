# Формат rules.json

Файл `rules.json` лежит **в корне папки с нормами**, которую выбирают в окне плагина.
Это не нормы, а выписки из них: документ, пункт, короткая цитата и значение.
Плагин читает только этот файл и ничего не берёт из памяти. Пример: `rules/rules.example.json`
(значения в нём нулевые и помечены «ЗАПОЛНИТЬ», его нельзя использовать как есть).

| Поле | Смысл |
|------|-------|
| `id`, `title` | идентификатор и название правила |
| `check` | `door-width`, `door-swing`, `stair-width` (совпадает с id проверки) |
| `document`, `clause`, `quote` | документ, пункт и цитата для отчёта |
| `minWidthMm` | минимальная ширина в мм (двери, марши) |
| `when.roomNameContains` | правило относится к двери, если название помещения по любую сторону содержит одну из подстрок |
| `when.typeNameContains` | то же по названию семейства и типа |
| `when.levelContains` | то же по названию уровня |
| `fromRoomNameContains`, `toRoomNameContains` | для `door-swing`: эвакуация идёт из помещений первого списка в помещения второго |

Пустой или отсутствующий список в `when` означает «любые». Если в модели у двери нет данных (ширина, дуга
открывания на плане), в отчёт попадает строка «Нет данных», а не «Нарушение».

## Что сейчас реализовано

- A.1.1 ширина дверей по параметру двери (не в свету);
- A.1.3 ширина лестничных маршей (площадки пока нет);
- A.1.4 открывание дверей: сторона открывания берётся по символической дуге двери на плане, помещения по обе стороны
  определяются по точкам в 0,8 м от двери. Работает, только если у семейства двери есть дуга на плане.

Остальные отмеченные проверки попадают в отчёт со статусом «Не реализовано».
