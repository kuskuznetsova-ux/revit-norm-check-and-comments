# Формат rules.json

Файл `rules.json` лежит **в корне папки с нормами**, которую выбирают в окне плагина.
Это не нормы, а выписки из них: документ, пункт, короткая цитата и значение.
Плагин читает только этот файл и ничего не берёт из памяти. Пример: `rules/rules.example.json`
(значения в нём нулевые и помечены «ЗАПОЛНИТЬ», его нельзя использовать как есть).

| Поле | Смысл |
|------|-------|
| `id`, `title` | идентификатор и название правила |
| `check` | `door-width`, `door-swing`, `stair-width` (совпадает с id проверки) |
| `document`, `edition`, `clause`, `quote` | документ, его редакция, пункт и цитата для отчёта |
| `section` | раздел (вкладка Excel): «Пожарная безопасность», «Жилые здания» и т.д.; если не указан, берётся по подгруппе |
| `subgroup` | подгруппа проверок, например `A.1` |
| `approvedBy`, `approvedOn` | кто и когда утвердил правило; **без утверждения плагин правило не применяет** |
| `quoteHash` | контрольная сумма текста цитаты, по ней плагин замечает изменение нормы |
| `minWidthMm` | минимальная ширина в мм (двери, марши) |
| `when.roomNameContains` | правило относится к двери, если название помещения по любую сторону содержит одну из подстрок |
| `when.typeNameContains` | то же по названию семейства и типа |
| `when.levelContains` | то же по названию уровня |
| `fromRoomNameContains`, `toRoomNameContains` | для `door-swing`: эвакуация идёт из помещений первого списка в помещения второго |

Пустой или отсутствующий список в `when` означает «любые». Если в модели у двери нет данных (ширина, дуга
открывания на плане), в отчёт попадает строка «Нет данных», а не «Нарушение».

## Что сейчас реализовано

- A.1.1 ширина дверей по параметру двери (не в свету);
- A.1.3 ширина лестничных маршей (площадки пока нет);
- A.1.4 открывание дверей: сторона открывания берётся по символической дуге двери на плане, помещения по обе стороны
  определяются по точкам в 0,8 м от двери. Работает, только если у семейства двери есть дуга на плане.

Остальные отмеченные проверки попадают в отчёт со статусом «Не реализовано».

## Актуальность правил (план)

Правило относится к конкретной редакции документа. При запуске плагин сверяет каждое правило с корпусом
текста из выбранной папки:

- пункт найден, цитата совпала: **актуально**;
- пункт найден, текст изменился: **проверить** (не применяется, пока не подтверждено);
- пункта нет: **устарело**.

Правила нескольких редакций одного документа хранятся рядом. Сверка по корпусу будет добавлена вместе
со сборкой корпуса из PDF.

## Правила в Excel

В окне плагина две кнопки:

- **Правила в Excel** выгружает `rules.json` из папки с нормами в таблицу: одна строка на правило и **одна вкладка на раздел** («Пожарная безопасность», «Жилые здания», «Общественные здания», «МГН», «Стоянки» и другие; документ указан в колонке).
- **Правила из Excel** загружает таблицу обратно в `rules.json`; старый файл сохраняется как `rules.json.<дата>.bak`.

Утверждение: заполните колонки «Утвердил» и «Дата» у проверенных правил. Списки значений в колонках
«Помещения содержат», «Тип содержит», «Уровень содержит», «Эвакуация из/в помещения» перечисляются через `;`.
Шапку таблицы менять нельзя: колонки находятся по названию. При загрузке читаются все вкладки с такой шапкой; `id` правил должен быть уникальным во всём файле. Новый раздел (например, «Высотные здания») добавляется новой вкладкой с той же шапкой; название вкладки станет разделом правил, если колонка «Раздел» пуста.
